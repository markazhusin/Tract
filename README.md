# Tract — локальный-first P2P messenger

## Что теперь есть

1. Регистрация устройства по одному паролю.
2. Локальная выдача криптоключа устройству.
3. Вход в аккаунт после выхода через пароль.
4. Стабильный `userId` аккаунта и отдельный session `peerId`.
5. Hosted handshake через signaling host.
6. Invite link и QR для входа в одну комнату.
7. Добавление контакта по `userId`.
8. Переименование собственного профиля и локальный alias для контакта.
9. Удаление истории чата и удаление контакта.
10. История и контакты хранятся в `IndexedDB`.

## Архитектура Tract

- Аккаунт создаётся локально в браузере.
- На сервер не уходит приватный ключ.
- Сервер нужен только для handshake, presence, SDP и ICE.
- Сообщения идут peer-to-peer через WebRTC Data Channel.
- Invite link содержит только параметры входа в комнату: frontend URL, signaling URL и `room`.

## Запуск

```bash
npm install
npm start
```

Это поднимет:

- frontend на `http://127.0.0.1:5173`
- signaling host на `http://127.0.0.1:8877`

Frontend запускается на `0.0.0.0`, поэтому его можно открыть из локальной сети и удобно пробрасывать наружу через tunnel или reverse proxy.

## Onboarding

1. При первом запуске пользователь вводит только:
   - отображаемое имя
   - пароль
2. Приложение локально генерирует ключевую пару.
3. Аккаунту автоматически назначается `userId`.
4. При выходе из аккаунта повторный вход делается тем же паролем.

## Invite / QR / Add by ID

1. Укажи `signalingUrl` и `room code`.
2. Нажми `Handshake`.
3. Приложение соберёт invite link и QR.
4. Любой пользователь, открывший эту ссылку на публичном frontend URL, попадёт в ту же комнату.
5. Контакт можно добавить вручную по `userId`.

## Публичная ссылка

`localhost` сам по себе не является публичной ссылкой для всех. Чтобы в приложение мог войти кто угодно по invite link, нужен один из вариантов:

- публичный frontend URL
- tunnel на локальную машину
- reverse proxy / VPS / static hosting для frontend

Для этого в UI есть поле `Public app URL`. Если frontend опубликован, именно этот URL попадает в invite link и QR.

## Что сервер не делает

- не хранит сообщения
- не хранит приватные ключи
- не авторизует аккаунты
- не является центральным message broker

Он только помогает peers найти друг друга и выполнить handshake.

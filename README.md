# Tract

Локальный-first P2P messenger с входом по логину и паролю.

## Что есть

1. Регистрация по логину вида `@login` и паролю.
2. Автоматический вход после перезагрузки приложения, пока пользователь явно не нажал `Выйти`.
3. Единое пространство без пользовательских комнат.
4. Поиск и добавление контакта по `@login`.
5. Пользователи не появляются в списках автоматически: чат создается только после добавления по логину или входящего сообщения.
6. Локальная история сообщений и контактов в `IndexedDB`.
7. Удаление выбранных сообщений у себя или у всех.
8. Очистка истории чата у себя или у всех.
9. P2P-доставка через WebRTC и fallback через signaling relay.

## Запуск

### Production (Go backend)

```bash
go build -o tract-server && ./tract-server
```

Сервер собирает frontend из `dist/` (если есть) и signalling API на `http://0.0.0.0:8877`.

Данные хранятся в директории `./data/` (создаётся автоматически). При деплое **обязательно подключите volume / persistent disk** к этой директории, иначе после перезапуска/редеплоя пользователи потеряют аккаунты.

Для production сборки frontend:

```bash
npm install && npm run build
go build -o tract-server && ./tract-server
```

### Разработка

```bash
npm install
npm run dev    # Vite dev server на порту 5173 + Go backend на 8877
```

В development Vite проксирует API-запросы на Go backend.

## Как пользоваться

1. Создайте аккаунт с логином `@login` и паролем.
2. Передайте другу ссылку на приложение.
3. Найдите друга по его `@login` в поиске над чатами или на вкладке контактов.
4. Откройте чат и отправьте сообщение.

Сервер не хранит приватные ключи и историю сообщений. Он нужен для presence, поиска онлайн-peer по логину, WebRTC handshake и очереди signaling-сообщений.

## Суперпользователь @creator

После запуска сервер генерирует одноразовый bootstrap-инвайт и печатает его в консоль:

```
=== ADMIN BOOTSTRAP INVITE ===
Register the superuser at: inv-XXXXXXXX
URL: ?invite=inv-XXXXXXXX
==============================
```

Чтобы получить доступ к @creator:

1. Откройте приложение по ссылке с параметром `?invite=inv-XXXXXXXX` (например, `http://localhost:8877/?invite=inv-XXXXXXXX`).
2. Зарегистрируйте аккаунт с **именем** (display name) строго равным `@creator`.
3. После входа и подключения к сети появится панель администратора: управление пользователями, создание инвайтов, бан.

Инвайт одноразовый — после регистрации он сгорает. Если нужно пересоздать, удалите `data/invites.json` и перезапустите сервер (или создайте новый через панель администратора).

## Деплой на Railway (GitHub)

В репозитории уже есть `railway.json` и `Dockerfile`:

- **build:** `docker build` — собирает frontend + Go binary
- **start:** `./tract-server` слушает `PORT` и отдаёт статику из `dist/`

После пуша в GitHub Railway сам собирает и поднимает сервис. Домен Railway уже с **HTTPS**.

1. Закоммитьте и запушьте изменения.
2. Дождитесь успешного деплоя в Railway.
3. Откройте ваш `*.up.railway.app` (или свой домен).
4. На телефоне: «Добавить на главный экран» / «Установить приложение».

Signaling URL подставляется с того же origin, что и страница.

### Офлайн-сообщения

Текстовые сообщения и сигналы звонка сохраняются на сервере в `data/message-inbox.json` по логину `@user` (не по сессии peer). Получатель увидит их после входа — даже через сутки и после выхода на всех устройствах.

### Сохранение данных между деплоями

Сервер хранит все данные (identity-блоб, инвайты, группы, инбокс, аватары, профили) в директории `./data/`. При деплое:

| Файл | Что хранит |
|---|---|
| `data/identity-store.json` | Зашифрованные identity-блобы пользователей |
| `data/invites.json` | Инвайт-коды |
| `data/groups.json` | Группы и участники |
| `data/message-inbox.json` | Офлайн-сообщения |
| `data/banned-users.json` | Забаненные пользователи |
| `data/avatars/` | Аватарки |

**Без persistence пользователи потеряют доступ к аккаунтам при редеплое**, так как сервер не хранит пароли и не может восстановить identity-блоб.

**Railway:** подключите volume c путём `/data` (working directory — `/app`, data пишется в `./data` относительно CWD).
**Docker:** пробросьте volume: `-v /host/path:/app/data`.

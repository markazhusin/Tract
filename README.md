# Tract

Локальный-first P2P-мессенджер. **Вход свободный, администраторов нет.**
Личность — это криптографический ключ: ID выводится из публичного ключа
автоматически, его нельзя занять, подделать или отобрать. Отображаемое имя
произвольное и может повторяться у разных людей — это лишь подпись, а не адрес.

Сервер сейчас существует только для демонстрации (presence, поиск онлайн-peer
по ID, WebRTC-handshake, очередь офлайн-сообщений). По замыслу (см.
`Tract_Новый_мир_v2.md`) он не нужен: каждое устройство — узел сети.

## Что есть

1. Регистрация без приглашений и без админов: имя + пароль, ID берётся из ключа.
2. Автоматический вход после перезагрузки, пока не нажат `Выйти`.
3. Единое пространство без пользовательских комнат.
4. Добавление контакта по его ID (ключу).
5. Пользователи не появляются в списках сами: чат создаётся после добавления по ID или входящего сообщения.
6. Локальная история сообщений и контактов в `IndexedDB`.
7. Удаление выбранных сообщений у себя или у всех.
8. Очистка истории чата у себя или у всех.
9. P2P-доставка через WebRTC (аудиозвонки и чаты) с fallback через signaling relay.
10. Звонки рассчитаны на работу по всему миру, с VPN и без: STUN + публичный TURN
    (UDP/80, TCP/443) пробивают симметричный NAT и фаерволы. Для приватности и
    надёжности поднимите свой coturn (см. ниже).

## Запуск

### Production (Go backend)

```bash
npm install && npm run build
go build -o tract-server && ./tract-server
```

Сервер отдаёт frontend из `dist/` (если собран) и signalling API на `http://0.0.0.0:8877`.
Данные пишутся в `./data/` (создаётся автоматически). **При деплое подключите
volume / persistent disk** к этой директории, иначе после редеплоя пользователи
потеряют доступ к аккаунтам (сервер не хранит пароли и не может восстановить ключ).

### Разработка

```bash
npm install
npm run dev    # Vite dev server (5173) + Go backend (8877)
```

В development Vite проксирует API-запросы на Go backend.

## Как пользоваться

1. Создайте аккаунт: введите имя и пароль. Ваш ID появится в профиле — это ваш адрес.
2. Передайте другу свой ID (или ссылку на приложение).
3. Добавьте друга по его ID в поиске над списком чатов.
4. Откройте чат, пишите и звоните.

Сервер не хранит приватные ключи и не видит содержимое сообщений (E2E на устройстве).

## Свои TURN-серверы (надёжные звонки)

Публичный TURN — это запасной вариант. Для стабильных звонков по всему миру
поднимите coturn и передайте его серверу через переменные окружения:

```bash
TURN_URLS="turn:turn.example.com:3478,turns:turn.example.com:5349?transport=tcp"
TURN_USERNAME=...
TURN_CREDENTIAL=...
```

Сервер отдаёт их клиенту через `GET /ice`, и клиент предпочитает их публичным.

## Деплой на Railway (GitHub)

В репозитории есть `railway.json` и `Dockerfile`:

- **build:** `docker build` — собирает frontend + Go binary
- **start:** `./tract-server` слушает `PORT` и отдаёт статику из `dist/`

После пуша в GitHub Railway сам собирает и поднимает сервис (домен уже с HTTPS).

1. Закоммитьте и запушьте изменения.
2. Дождитесь деплоя.
3. Откройте `*.up.railway.app` (или свой домен).
4. На телефоне: «Добавить на главный экран» / «Установить приложение».

Signaling URL берётся с того же origin, что и страница.

### Офлайн-сообщения

Текстовые сообщения и сигналы звонка сохраняются на сервере в
`data/message-inbox.json` по ID получателя. Их видно после входа — даже спустя
сутки и после выхода на всех устройствах.

### Данные на сервере

| Файл | Что хранит |
|---|---|
| `data/identity-store.json` | Зашифрованные identity-блобы (публичные данные + зашифрованный ключ) |
| `data/groups.json` | Группы и участники |
| `data/message-inbox.json` | Офлайн-сообщения |
| `data/avatars/` | Аватарки |

**Без persistence пользователи потеряют доступ к аккаунтам при редеплое** —
сервер не хранит пароли и не может восстановить identity-блоб.

**Railway:** volume на `/data` (working directory `/app`, данные пишутся в `./data`).
**Docker:** `-v /host/path:/app/data`.
